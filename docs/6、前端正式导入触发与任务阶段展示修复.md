# AI 面试题库系统：前端正式导入触发与任务阶段展示修复

## 一、当前问题

后端已经完成并测试了正式知识导入链路，包括知识提取、知识去重、知识库归属、知识保存、向量同步和 KnowledgeRelationAgent 关系处理。

当前前端存在两个问题：

1. 管理员上传文档并创建 ImportTask 后，没有自动调用正式处理接口：

   `POST /api/v1/import-tasks/{task_id}/run`

2. 导入任务的处理阶段显示可能与后端返回的 step 字符串不匹配，导致阶段展示错误或无法识别。

本任务只修改 Vue3 管理后台 `admin-web/`，不修改后端业务代码。

## 二、开始前必须检查

先检查以下内容：

1. 当前上传文档、创建 ImportTask 的页面和 API 方法。
2. 当前导入任务详情及进度展示组件。
3. 前端现有的任务状态轮询逻辑。
4. 前端是否仍然调用 `/simulate`，以及正式流程是否错误地使用了模拟数据。
5. 允许只读检查 `backend/` 中的 ImportTask Router、Schema、状态/阶段枚举和 Service，确认真实接口契约；严禁修改 backend。
6. 以实际代码和真实接口响应为准，不得根据本文示例猜测字段名称、状态枚举或响应结构。

优先复用当前 API 封装、鉴权、响应解析、页面组件和 UI 风格，不要重写整个导入页面。

## 三、实现上传后自动执行正式导入

预期流程：

1. 管理员选择知识库并上传文档。
2. 前端调用现有创建导入任务接口。
3. 从真实响应中获取 task_id。
4. 创建任务成功后，自动调用：

   `POST /api/v1/import-tasks/{task_id}/run`

5. 正确处理接口返回值。如果 `/run` 只表示任务已提交或开始执行，不要提前显示导入成功。
6. 进入任务处理中状态，开始定时查询：

   `GET /api/v1/import-tasks/{task_id}`

7. 根据查询结果更新状态、当前阶段、真实进度和处理结果。
8. 任务进入实际定义的终态后停止轮询并展示统计结果。

要求：

- 只有成功创建任务并取得有效 task_id 后，才能调用 `/run`。
- 上传或创建任务失败时，不调用 `/run`。
- 同一任务的 `/run` 请求不得因组件重复渲染、状态更新、页面重挂载或重复点击而被反复触发。
- 提交期间应适当禁用重复操作，并向用户展示明确的错误提示。
- 如果 `/run` 调用失败，不得假装任务已开始或已成功；展示真实错误，并根据实际任务状态提供合理的重试方式。
- 页面刷新或重新进入已有任务详情时，应查询现有任务。如果任务仍在处理中，恢复轮询，不要自动重复执行 `/run`。
- 轮询请求必须避免重叠。组件卸载时清理定时器或轮询任务；离开页面不应取消后端正在运行的导入任务。
- 遵循现有统一响应格式，正确判断 HTTP 状态码以及业务响应中的 code/message/data。

## 四、修复处理阶段映射

先从后端实际代码及真实响应中整理完整的 status、step 值，建立唯一的前端映射表。

要求：

1. 将任务状态和处理阶段分开映射，不能混为一个字段。
2. 将阶段字符串到中文展示名称的转换集中到公共工具、常量或任务状态映射模块。
3. 映射必须使用后端真实枚举或真实返回值，不能仅使用开发者猜测的字符串。
4. 不要同时维护大小写、下划线形式不一致的多套无依据映射。
5. 前端应正确显示后端真实返回的进度，不要通过前端猜测当前阶段并自行伪造百分比。
6. 后端没有返回阶段时，展示合理的等待或未知阶段提示。
7. 遇到未知 step 时，显示通用处理中提示，必要时附带原始 step，方便后续补充映射；不得错误映射到其他阶段。
8. 对 SUCCESS、PARTIAL_SUCCESS、FAILED、CANCELLED 等终态，必须以当前后端真实定义为准，正确停止轮询并展示最终统计及错误信息。

建议将阶段映射与状态映射独立管理，并添加单元测试，覆盖后端当前实际支持的每一种 status/step。

## 五、真实数据显示要求

前端必须显示任务详情 API 返回的真实信息，包括项目实际存在的：

- 任务状态。
- 当前处理阶段。
- 处理进度。
- 知识候选数量。
- 新增知识点数量。
- 重复知识点数量。
- 合并知识点数量。
- 失败数量及失败原因。

仅展示后端实际返回的字段。对于当前接口没有提供的信息，不要伪造默认统计数据。

知识库名称或 ID 应来自当前任务的真实归属，不能因为用户切换当前页面中的知识库选择，就错误修改已创建任务的展示归属。

## 六、测试要求

至少覆盖以下场景：

1. 上传成功后，前端自动调用 `/run`。
2. 上传失败时，不会调用 `/run`。
3. 创建任务响应缺少有效 task_id 时，前端能给出清楚错误。
4. `/run` 返回任务已提交时，前端继续轮询，而不是提前结束。
5. 处理阶段变化时，页面能正确显示对应中文文案。
6. 未知 step 能显示兜底提示，不会导致页面报错。
7. 任务 SUCCESS 后停止轮询并显示结果。
8. 任务 PARTIAL_SUCCESS 或 FAILED 时显示相应状态和错误信息。
9. 页面刷新或重新进入处理中的任务时，能够恢复查询状态，且不重复执行 `/run`。
10. 离开页面后轮询被清理，不产生持续的重复请求。
11. 多次点击上传、创建任务或触发操作，不会造成同一任务重复运行。
12. 原有登录、知识点管理、知识库筛选、导入任务列表和详情等功能保持正常。

优先使用项目已有测试框架。若当前缺少自动化测试，应至少提供可复现的接口联调步骤，并清楚标记哪些测试实际执行过。
