# DSH：AI 出题链路故障修复与题目状态统一

## 一、背景

管理员 Web 前端已经完成开发，并使用真实后端 API 进行了联调。

目前创建 AI 出题任务可以成功，但后台执行生成时失败。

真实错误：

`'knowledge_base_id' is an invalid keyword argument for Question`

同时发现题目状态存在大小写不一致的问题。

## 二、任务一：修复 AI 出题链路

请检查：

1. `Question` ORM 模型定义。
2. `QuestionGenerateAgent` 创建题目的逻辑。
3. 知识库、知识点、题库之间的模型关系。
4. `QuestionRepository` 及题目保存逻辑。
5. 生成任务的执行和结果统计逻辑。

找出为什么创建 `Question` 时传入了不支持的 `knowledge_base_id`。

根据项目现有数据模型修复，不允许为了消除异常就盲目向 Question 增加字段或创建重复关联。

保证生成题目能够正确保存：

- `question_bank_id`
- 题目与知识点的关联关系
- 题目类型、难度、题干、答案、选项
- 正确的初始审核状态
- 对应生成任务的关联信息（使用项目现有字段和关系）

## 三、任务二：统一题目状态

统一数据库存储值和 API 返回值：

- `pending_review`
- `published`
- `rejected`
- `disabled`

禁止继续写入 `DISABLED` 等大写状态。

检查历史数据，必要时通过 Alembic 安全迁移统一已有值。

确保列表筛选、审核、下架接口均使用统一状态。

## 四、任务三：补充测试

必须验证：

1. 创建任务成功。
2. 后台实际执行成功。
3. 成功生成至少一道真实题目并保存数据库。
4. 题目归属正确的题库。
5. 题目关联正确的知识点。
6. 题目初始状态为 `pending_review`。
7. 生成任务成功数量、失败数量与实际保存数据一致。
8. 发布后状态变成 `published`。
9. 下架后状态为 `disabled`。
10. 原有题目审核、编辑保护和其他测试不回归。

至少执行一轮真实后端生成流程，不能只用 Mock 或直接构造 Question 对象的单元测试代替。

## 五、开发约束

- 只修改 `backend/`。
- 不修改 `frontend/`。
- 不重新开发 QuestionDecisionAgent。
- 不重构无关模块。
- 不为了绕过错误盲目增加 ORM 字段。
- 保留已有数据库数据。
- 需要数据库结构调整时使用 Alembic。

## 六、交付要求

输出：

`QUESTION_GENERATION_HOTFIX_REPORT.md`

报告说明：

- 根本原因。
- 修改的文件。
- 数据库是否变更。
- 修复前后的行为。
- 真实生成测试结果。
- 题目状态统一情况。
- 回归测试结果。
- 仍然存在的问题。
